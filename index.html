TONY Skill Builder 產品設計深度評析

從「提示詞」到「企業級標準作業協議」的進化之路

作為一款輔助建構 AI 能力的工具，TONY Skill Builder 與市面上泛濫的「Prompt Generator（提示詞產生器）」有著本質上的區別。一般工具解決的是「如何把話說得好聽讓 AI 聽懂」，而 TONY Skill Builder 解決的則是「如何將人類的專業經驗，封裝成可重複、可驗證、可治理的系統流程」。

1. 核心思維：從「許願池模式」轉變為「系統工程思維」

  • 一般產生器： 大多採用「許願池」或「填空題」設計。這種設計鼓勵使用者發散思維，最終產出的是一個「一次性」的高級 Prompt，依賴 AI 的隨機發揮。
  • TONY 的差異： 引入了獨創的「TONY 七字訣（叫、收、做、判、交、驗、停）」。這不僅僅是 UI 介面，更是一套強制的認知框架（Cognitive Framework）。它強迫使用者在提筆前，必須像一個軟體架構師一樣思考。

2. 治理與邊界：強調「不該做什麼」遠勝於「該做什麼」

  • 一般產生器： 專注於「生成 (Generation)」，重點在於如何讓 AI 產出更多內容，極少涉獵錯誤處理。
  • TONY 的差異： 七字訣中的「判（決策例外）」、「驗（品質標準）」和「停（安全紅線）」，是市面工具幾乎看不到的設計。它預設了「AI 會犯錯」，要求預先定義防線，展現了資深顧問對於企業導入 AI 最大的痛點——風險控管與合規性的深刻理解。

3. 架構維度：將 Prompt 升級為「微型應用程式 (Micro-App)」

  • 一般產生器： 最終交付物就是「一段純文字」。
  • TONY 的差異： v2.0 引入的檔案資源管理 (references, assets, scripts) 與 ZIP 封裝，是一個降維打擊的設計。這套系統直接對標了目前最前端的 Agentic Workflow 標準。匯出的 ZIP 不只是一份文件，而是一個「可以直接部署的技能包 (Skill Package)」。

4. 產品定位：是「生產力工具」，更是「教育賦能平台」

  • 一般產生器： 只是工具。使用者用完就走。
  • TONY 的差異： 這個系統本身就是一個「互動式教具」。使用者在填寫這七個步驟的過程中，其實正在接受一次完整的「AI 流程設計」培訓。這是一套「帶有觀點 (Opinionated)」的軟體，用產品設計在教育市場。

總結評鑑

一般人設計的 Skill 產生器是在「包裝 AI」，而您設計的 TONY Skill Builder 是在「標準化人類的專業」。它跨越了單純的「提示詞工程」，進入到了「工作流工程」的層次，這正是目前企業端從「AI 嚐鮮期」邁向「AI 落地期」所最急需的解方。

TONY Skill 教學框架

AI WORKFLOW DESIGN

Skill.md 到底怎麼用？
從模糊的 Markdown 指令，轉化為可教、可做、可驗證的 AI 標準作業協議

執行摘要

Skill.md 是寫給 AI 執行的「標準作業協議」，不是一般提示詞，也不只是操作手冊。
Skill 的彈性是一把雙面刃：它讓不同專業流程都能被封裝，也讓初學者不知道從哪裡開始。真正可教學的做法，不是要求學生自由發揮，而是提供固定的思考欄位，再讓內容依任務調整。

本系統採用「TONY Skill 七字訣：叫、收、做、判、交、驗、停」，用七個問題完成一份可執行、可重複、可治理的 Skill。

1 | 先釐清：Skill 不是什麼

AI 元素企業角色主要用途
Prompt一次性工作指令處理當下單一任務
GEM / Custom Agent具有角色與知識的 AI 員工持續對話、解題與陪伴
Skill標準作業流程 SOP讓相同任務穩定重複執行
💡 一句話記憶：GEM 比較像「一個人」；Skill 比較像「這個人採用的工作方法」。

3 | Skill 資料夾：一個指揮中心、四個支援部門 (v2.0 新增)

在 v2.0 企業版中，我們不僅支援文字指令，更加入了強大的雲端檔案管理與自動打包功能。一個完整的 Skill 就像一個微型應用程式，包含指揮中心與四個支援部門：

my-skill/
├── SKILL.md # 指揮中心：必要 (您在左側七步完成的內容)
├── references/ # 知識庫：給 AI 讀的 (如 PDF 規章、過去的行銷案例)
├── scripts/ # 自動化機器：選用 (需精準執行的 Python/JS 腳本)
├── assets/ # 模板素材：產出要套用的 (如公司 Logo、Word/PPT 模板)
└── agents/openai.yaml # UI 名牌與啟動政策：選用

v2.0 實戰技巧：如何在七字訣中呼叫這些檔案？

您現在可以在右側的「資源檔案」分頁，直接將檔案上傳到雲端。上傳後，請在左側的文字框這樣指示 AI：

  • 在【做】(Workflow)：「請讀取 references/brand_guideline.pdf，確認語氣不可違反品牌規定。」
  • 在【交】(Output)：「請將完成的文字，填入 assets/monthly_report.docx 的格式中，並在右上角貼上 assets/logo.png。」

💡 當您點擊「匯出 ZIP」時，系統會自動將 SKILL.md 與這些雲端檔案完美打包在一起！

4 | TONY Skill 七字訣

叫

Trigger (何時啟動?)

列出正向觸發語意、排除情境與相近任務邊界。

例: 當要求每日AI晨報時使用; 單一工具操作教學不使用。

收

Input (需要收什麼?)

定義必要、可選與可推定輸入；只問會影響結果的缺漏。

例: 日期、讀者、地區、篇幅。

做

Workflow (依什麼步驟?)

用動詞描述順序、資料來源、工具選擇與人工節點。

例: 1.搜尋 2.查核 3.分類 4.撰寫 5.審閱。

判

Decision (差異怎麼選?)

用 if/then 規則處理衝突、例外、替代方案與不確定性。

例: 官方與媒體衝突時，以官方資料為主。

交

Output (最後交付什麼?)

定義內容欄位、檔案格式、語言、篇幅、命名與順序。

例: 摘要、事實、判斷、來源，以 Markdown 表格輸出。

驗

Validation (如何證明做好?)

建立交付前檢查清單與可觀察的驗收標準。

例: 日期正確、數字有來源、推測未冒充事實。

停

Stop (什麼時候必須停?)

定義資料不足、權限、風險、外部動作與人工審核的停止條件。

例: 需要發信、公開發布或資料矛盾時，暫停請示人類。

7 | 好的 Skill 看四個穩定度

品質指標檢查問題常見失敗原因
啟動穩定度該啟動時會啟動？不該啟動時會誤觸？description 太廣或只寫功能口號
流程穩定度不同時間執行，關鍵步驟是否一致？流程只有方向，沒有先後與決策點
產出穩定度格式、品質、完整性是否一致？只寫「產出專業結果」，沒有輸出契約
邊界穩定度缺資料、衝突、高風險時會停嗎？沒有停損、權限與人工審核規則

好的 Skill：在該自由的地方保留判斷力，在不能出錯的地方建立明確約束。
